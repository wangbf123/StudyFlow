# 结论与原文证据绑定的问答

问答返回结构化结论，每条结论绑定来源和原文引文。生成器的输出先经过确定性校验，再经过独立一次模型核验，最后提交消息、结论和引用。SSE 先发送核验状态，核验完成后才发送可见答案。

## 校验与拒答

- 仅接受严格 JSON `claims` 协议，拒绝重复字段、额外字段、代码围栏、尾随内容、旧文本答案以及超长输出。结论、引文和引用数量均有上限。
- `source_id` 必须来自本次检索的白名单，`quote` 必须是对应分片的连续原文。保存 SHA-256、generation 和 UTF-16 字符起止位置。网页使用文本插值和 `<mark>` 定位，不执行模型生成的 HTML。
- 核验前后均复查用户、知识库、文档状态、当前 generation 及内容摘要。核验器只返回 SUPPORTED、CONTRADICTED、INSUFFICIENT；格式错误、超时和服务失败都不放行结论。
- 第二次模型调用可用 `studyflow.evidence.verifier-model` 指定模型，默认复用配置模型。核验采用独立提示与请求；它仍可能误判，不能当作事实证明或独立人工评测。
- mock 模式只接受结论文字与原文引文完全相等，标记为 `EXTRACTIVE_ONLY` / `EXTRACTED`。此路径验证证据协议，不模拟语义准确率。

## 持久化和版本边界

V10 增加 `qa_claim`、引用快照及核验元数据。短事务中按“文档 → 知识库 → 分片”加共享锁，再次验证版本与所有权，原子保存消息、结论、引用；和文档重建/删除的写锁顺序一致。失败不保存未经核验的可见答案。

历史问答返回结论及引用。当前版本引用提供可高亮的字符位置；重建后的旧引用标记 `STALE_VERSION`，展示历史引文并不再提供当前原文偏移。删除文档后引用详情不可读；知识库删除后其历史问答不可读。该权限边界在查询时重新验证。

接口保持 `/api/qa/ask`、`/api/qa/ask/stream` 和历史消息接口，扩展 `claims`、`answerStatus`、`verificationMode`、核验耗时和 token 用量。引用详情在 `/api/qa/citations/{id}/chunk`。前端显示核验模式、结论的证据按钮及原文位置。

## 验证范围

`EvidenceAnswerSecurityTest` 覆盖严格协议、越权、伪造来源、引文不匹配、Unicode 位置、失效版本、矛盾/不足结论、核验超时和失败、核验中删除文档。`QaEvidencePersistenceMySqlTest` 使用生产 MyBatis mapper 和真实 InnoDB，检查原子回滚、锁竞争、删除/重建与历史读取。

完整 API 实验使用真实 MySQL、Redis、MinIO、Elasticsearch 和 CPU BGE，问答生成器为 extractive mock。没有配置真实生成模型密钥，因此未测真实模型的幻觉率、语义拒答准确率或提示注入成功率；已有模型核验测试使用受控响应验证协议和失败行为。

可用于简历的表述：实现结论与原文证据绑定的 RAG 问答，设计来源白名单、连续引文校验、版本与权限复查及核验失败拒答，并通过真实数据库并发测试验证引用保存与文档重建/删除的一致性。
