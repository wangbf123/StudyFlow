# ADR 001 · 可恢复、可解释的知识库工作台

日期：2026-10-15。状态：已实施。

## 业务目标

用户上传资料后能尽快检索，模型摘要短暂故障不影响已建立的知识索引；用户能够看见处理状态，判断检索采用了什么信号，并回到原文核对结论。工程上需要支持多实例会话、明确的重试边界和可观测运行状态。

## 决策

| 问题 | 选择 | 原因与取舍 |
|---|---|---|
| 摘要阻塞入库 | INDEX 成功后，事务内创建独立 SUMMARY 任务及 Outbox | 索引就绪与摘要状态独立；async 模式为摘要使用独立有界线程池，拒绝时由 Outbox 重试。两类任务共享 generation/token fencing，摘要仍有失败和输入截断边界。 |
| 向量重试成本与内存 | keyset 分页读取，每批独立保存向量，重试跳过有效同模型向量 | 工作内存随批次大小增长；INDEX 仍可重复写稳定 ID。整文件解析内存尚未改为流式。 |
| 检索排序难解释 | 保留原始召回排名，披露 RRF 贡献、候选过滤和降级原因 | 过滤无效片段不会抬高其余片段的原始排名。分数仅是排序信号。 |
| 运行状态不可见 | 所有权范围内的聚合统计、游标文档列表、当前版本任务视图 | 避免按文档逐条计数和深 OFFSET；保留旧列表接口兼容已有调用方。 |
| 会话仅存在单进程 | 官方 Sa-Token Redis Jackson 适配器 | 跨实例共享授权会话，应用重启可继续使用 token；依赖 Redis 可用性与其持久化策略。 |
| 监控与错误定位 | Actuator、Prometheus 缓存指标、请求 ID 与异步 MDC | 默认独立 loopback 管理端口；固定 stage/status 标签控制指标基数。 |
| 前端发布与流式边界 | 同源 API、开发代理、独立 SSE 解析器、AbortSignal、终止事件检查 | 支持反向代理部署；中文增量、CRLF、断流和认证失败有明确行为。 |
| 页面体积与维护 | Element Plus 按需组件/CSS、知识概览和检索组件分离 | 减少全量 UI 包加载；问答与 Agent 页面仍在 App.vue，继续逐步拆分。 |

## 一致性约束

文档 generation 是当前资料版本；MySQL 为权限、任务状态和版本的事实来源。可检索状态 SUCCESS 仅由主流水线发布，SUMMARY 的领取、失败和租约回收均不能将它改回 PROCESSING / FAILED。派生摘要输出只有通过当前 token、generation 与 ACTIVE 知识库检查后才能保存。

分批向量保存不推进阶段；只有处理全部分片后才推进到 INDEX。重试复用的是同一不可变 generation 下、模型名和维度一致且数值有效的向量，不是跨用户或跨模型全局缓存。

恢复扫描每轮有批次上限，按“文档 → 任务”锁顺序恢复或取消，再补写持久唤醒。ES 仍与 MySQL 最终一致，检索后复查归属、状态、generation 及正文内容；迟到写入由版本过滤和退役索引对账处理。

## 验证与未覆盖范围

真实 MySQL 验证摘要故障隔离、摘要租约耗尽、批次 fencing、恢复批次上限、文档游标过滤与统计权限。真实 ES 验证检索说明、模型不可用降级和同 generation 正文漂移过滤。前端测试覆盖增量流协议及失败边界。运行实验验证共享 token 跨实例与应用重启。

未将小样例检索分数当作生产质量保证；真实生成模型语义准确率、RocketMQ / Redis 集群故障和大规模容量需要独立实验。模型上下文、整文件解析和物理对象回收仍有文档化限制。
